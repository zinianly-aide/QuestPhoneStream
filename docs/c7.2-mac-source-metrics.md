# C7.2 Mac Sender source telemetry (local, CPU-validated)

This prepares later one-day RTX 4090 + Quest 3S performance measurements.
It does not alter signaling, WebRTC tracks, the Android control protocol,
SpatialPanel geometry, or headset rendering. It is based on the landscape
Mac/Quest fix branch and remains **unmerged, not device-verified**.

## Observability added

The existing Mac Sender detail line displays, while the LingBot video source
is active:

- `AI X.Xfps`: distinct JPEG frames fetched and drawn on the Mac canvas,
  calculated from a rolling last-64-unique-frame observation window;
- `fetch+draw p95 Nms`: HTTP fetch + JPEG decode + canvas draw duration,
  **not** an end-to-end viewer latency measurement;
- `last-frame Nms`: time since last fresh frame on the Mac canvas;
- `seq gaps N`: skipped source frame sequence identifiers as seen by Mac,
  which can be caused by the interactive Cloud policy **or** HTTP polling
  missing updates; it does not distinguish the cause by itself.

The regular Quest Spatial telemetry (head/controller) sequence remains separate.
Stats are also available from the same renderer window via:

```javascript
window.qpsAiVideoStats?.()
```

No extra HTTP polling is added to gather metrics; a 1s local-only UI refresh
reads already recorded counts. The track still primes a real frame before
`captureStream()` and macOS Sender's 30 FPS canvas capture cap is unchanged.

## CPU checks

```bash
cd apps/macos-sender
npm test
npm run build
```

`npm run build` now typechecks **both** Electron main and browser renderer +
AI bootstrap entrypoints, preventing unreported browser TypeScript errors.
The 64-sample window prevents long-running client-side telemetry growth.
